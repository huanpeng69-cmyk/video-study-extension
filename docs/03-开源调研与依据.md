# 视频学习助手｜开源调研与依据

> 调研日期：2026-10-19。GitHub 搜索及主要元数据采集于当日 02:26–02:28 UTC。  
> 范围：支持“B站 + Chrome/Edge 扩展 + 自带 API + 本地笔记”的选型，不是对所有同类产品的完整评测。  
> 本次做了固定版本源码、许可证和公开文档核对；未安装参考产品、未运行这些开源项目，也未做带 Key 的 API 或真实 B站字幕联调。

## 1. 研究结论

**建议独立实现产品核心，复用成熟工程基础，按模块借鉴开源项目。**

| 项目 | 主要价值 | 对本项目的定位 |
|---|---|---|
| Obsidian Web Clipper | 剪藏、Provider 分层、可编辑内容与 Markdown 输出 | 首版交互和模块分层参考；密钥保存另行设计 |
| WXT | MV3、TypeScript、侧栏入口与多浏览器构建组织 | 首版工程框架候选 |
| Bilibili-Evolved | 当前视频字幕列表、轨道选择与正文读取 | B站适配器的主要实现参考之一 |
| yt-dlp | 独立的 B站字幕读取、登录状态提示、字幕格式转换 | 对照验证；首版不打包 Python 下载器 |
| VideoLingo | 上下文分块、原译文对齐、音视频处理流程 | 借翻译设计，重处理留给后续本地助手 |
| BiliNote | 更完整的视频笔记产品，已有浏览器扩展 | 参考后续本地后端路线，首版不整体 fork |
| b-note | 很贴近的 B站侧栏字幕/总结流程 | 小项目对照；许可、存储和权限不满足直接复用前提 |

“比较成熟”不等于“星标多就能直接运行”。本次综合看近期推送、发布记录、具体实现、依赖成本、许可证及与产品边界的匹配度；运行可靠性仍需测试。

- [官方 FAQ](https://wiki.agnes-ai.com/en/docs/faqs)：区分 401、402、404、429、5xx，说明套餐/额度与请求速率限制。
- [Common Error Codes](https://wiki.agnes-ai.com/en/docs/code.md)：提供错误含义与处理建议。
- [Model Pricing](https://wiki.agnes-ai.com/en/docs/pricing.md)：包含当前价格与促销描述，不能当成长期固定价格。

FAQ 不同部分同时存在计费/套餐与免费服务描述。因此本方案以当前模型、Key 类型与控制台为准，不承诺永久免费、固定 RPM 或不存在额度限制，也不代用户进行付费请求。

<a id="d03"></a>
### D03 · Chrome Side Panel

[官方 Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)：API 标注 Chrome 114+ / MV3+；“Programmatically open the side panel”说明 open 从 Chrome 116 起可用且需要用户手势。本方案的侧栏入口来自此能力，Edge 仍需单独验证。

<a id="d04"></a>
### D04 · 跨域网络与消息代理

[官方 Cross-origin network requests](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)：

- Content Script 代表页面 origin 发起请求，仍受同源限制。
- 扩展 Service Worker/前台扩展页面在请求主机权限后可跨域访问。
- 主机权限中的路径部分不提供细粒度路径隔离，应用自身仍须做 URL 路径校验。
- “Limit content script access to cross-origin requests”明确提醒：不要接受 Content Script 请求任意 URL，避免被恶意页面借作通用代理。

所以本项目将模型请求放在可信扩展页面，并拒绝网页控制请求域名或鉴权头。

<a id="d05"></a>
### D05 · 按需主机权限

[官方 permissions API](https://developer.chrome.com/docs/extensions/reference/api/permissions)：说明运行时发现域名时可用 optional_host_permissions 的 `https://*/*` 声明，再通过 permissions.request 请求具体 origin；申请需源于用户手势。

本方案遵循“允许申请”和“已经取得授权”分离的规则，不能把 optional 声明表述成安装时已拥有全站权限。

<a id="d06"></a>
### D06 · 存储与密钥隔离

[官方 storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)：Storage areas 中说明 local 默认约 10 MB；session 在内存中、默认不向 Content Script 暴露、在浏览器重启或扩展重载/更新等情况下清空；sync 配额约 100 KB。local/sync 默认暴露给 Content Script 的行为可通过 setAccessLevel 调整。

本项目据此把默认 Key 放 session，敏感 local 数据限制为可信上下文，不把全文字幕和密钥放 sync。IndexedDB 的角色与事务能力还参考 [Service Worker 数据持久化说明](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。

<a id="d07"></a>
### D07 · MV3 Service Worker 生命周期

[官方生命周期文档](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle) 的 “Idle and shutdown” 列出通常终止条件，包括 30 秒闲置、单次长请求/事件和 fetch 响应等待限制；同时要求为意外终止设计持久化恢复。

本项目选择扩展页面执行 AI、逐块持久化检查点；不使用常驻 Service Worker 假设，也不把前端取消请求等同服务商停止计费。

## 5. 横向取舍：具体借什么、自己做什么

| 主题 | 对照得到的事实 | 本项目选择（建议） |
|---|---|---|
| 工程外壳 | WXT 能处理 MV3 侧栏；BiliNote 扩展需要独立后端 | 使用 WXT，首版不引入后端 |
| B站字幕 | Bilibili-Evolved 与 yt-dlp 有可交叉核对的读取实现 | 建平台适配器，真实样本验证后锁接口行为 |

| 笔记持久化 | Clipper 的配置同步不是本地笔记库；b-note 的历史有截断 | IndexedDB 独立 Note/Transcript/Artifact，提供备份 |
| API 地址 | Clipper 直接使用 endpoint；Agnes 文档给 Base URL 与路径 | 明确基地址语义，展示最终 URL，防重复 `/v1` |
| 权限与密钥 | 全站权限和 storage.sync 均有真实案例 | 可选主机授权、session Key、导出白名单 |
| 无字幕视频 | BiliNote/VideoLingo/b-note 的相关流程有额外运行或服务依赖 | 首版文件导入，ASR 作为独立能力扩展 |

## 6. 边界问题与拟验证演示

这些是后续验证脚本的设计，不是已运行结果：

1. **分 P / 迟到响应演示**：打开 P1 获取字幕，立即切 P2，让 P1 响应最后返回；字幕视图和保存记录都必须仍属于各自 CID。
2. **API 域名授权演示**：拒绝模型主机权限；AI 停止，本地手写/导出继续。换域名时显示新目标并重新授权，不转发旧 Key 到重定向位置。
3. **长任务中断演示**：翻译到第几块后关闭面板，重新打开；已提交结果仍在，只恢复未完成块，并告知未收到结果的请求可能已计费。
4. **引用失真演示**：模拟模型返回不存在的 Cue ID；不能靠删除该引用让校验变绿，必须使对应批次失败。
5. **笔记保护演示**：用户编辑个人理解后重新总结；手写内容保持不变。恢复损坏备份时当前资料也不能被清空。
